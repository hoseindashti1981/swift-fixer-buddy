# مجموعه اولیه ارزیابی جست‌وجو

این ۱۰۰ عبارت برای طراحی آزمون پیشنهاد شده‌اند و از واژگان محتوای پروژه و سناریوهای بررسی قبلی ساخته شده‌اند. عبارت‌ها گزارش ثبت‌شده از ۱۰۰ جست‌وجوی واقعی کاربر نیستند. پاسخ فنی و شناسه کارت مورد انتظار باید در فاز ورود محتوا تعیین و بازبینی شود.

## روش امتیازدهی

- واحد نتیجه، کارت یا بخش قابل لینک از یک مطلب است.
- برای هر عبارت، شناسه‌های پاسخ قابل قبول و وضعیت پوشش ثبت شود.
- وضعیت پوشش یکی از «موجود و تأییدشده»، «نیازمند اصلاح»، «نیازمند تولید» یا «رفع ابهام» باشد.
- تطبیق قصد کاربر کافی نیست. پاسخ باید با مدل، معماری و حالت دستگاه سازگار باشد.
- برای ورودی مبهم مانند E01، درخواست انتخاب دستگاه یا فهرست تفکیک‌شده مدل‌ها نتیجه درست محسوب می‌شود.
- برای گروه ایمنی، اقدام ایمن باید بالاتر از راهنمای تعمیر نمایش داده شود. پاسخ فاقد شواهد، تشخیص قطعی ندهد.
- هر گروه ۵ عبارت دارد. هنگام تنظیم رتبه‌بندی، چهار عبارت برای توسعه و عبارت پنجم برای ارزیابی کنار گذاشته شود. ارزیابی نهایی به عبارت‌های تازه کاربر نیز نیاز دارد.
- در فاز صفر پاسخ‌های فنی برچسب نخورده‌اند. از این جدول به‌تنهایی نمی‌توان دقت موتور را محاسبه کرد.
